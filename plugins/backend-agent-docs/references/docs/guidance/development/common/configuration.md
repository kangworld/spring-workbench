# 공통 설정 기준

- 설정은 실제 소비 코드의 책임 경계에서 관리합니다. 이름이 비슷하다는 이유로 임의의 공통 설정 파일이나 패키지에 모으지 않습니다.
- 환경 의존 값과 비밀값은 코드에서 분리합니다. 문서에는 키, 형식, 등록 위치와 비밀이 아닌 예시를 남깁니다.
- 설정을 추가할 때 소비자, 키, 타입, 단위, 기본값, 유효성 조건과 덮어쓰기 우선순위를 확인합니다. 쓰이지 않는 키나 테스트 통과용 값을 추가하지 않습니다.
- 운영 정책과 제품 계약의 기본값은 권위 있는 설정 위치에 둡니다. 필수 설정이 없으면 안전한 실행 여부를 판단하고 필요한 경우 기동 시 실패합니다.

## 운영 설정 검증

- timeout, retry, backoff, circuit breaker, pool, batch size와 scheduler 주기는 비용·부하·실패 의미를 기준으로 정합니다.
- retry는 멱등성, 중복 처리와 result-unknown 위험을 확인한 뒤 적용합니다.
- 환경별 차이는 배포 문서나 프로젝트 고유 지침에 기록하고 실제 실행 환경별 기동으로 검증합니다.
- credential, token, private key와 webhook URL을 문서·Git·명령 출력·로그에 남기지 않습니다.
