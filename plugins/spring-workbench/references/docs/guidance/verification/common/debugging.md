# 백엔드 디버깅

버그 조사에서 기대 동작, 실제 동작이 처음 갈라지는 경로, 그 차이를 설명하는 증거를 연결합니다.

1. API·서비스 계약, 실행 환경, 빌드나 배포 버전, 시각과 요청 식별자를 확인합니다.
2. 관련 경로를 Controller, Service, Repository·DAO 또는 외부 호출 순서로 따라가며 첫 불일치 지점을 좁힙니다.
3. 요청·응답, 테스트, 로그, DB 상태를 대조합니다. 공통 모듈 동작이면 실제 선택된 의존성 버전을 확인합니다.
4. 수정 전에 실패를 재현하거나 재현이 불가능한 이유와 근거 수준을 밝힙니다. 가능하면 실패 경로를 잡는 회귀 테스트를 남깁니다.

성공 응답과 내부 처리 성공은 각각 확인합니다. 관찰된 배포 버전과 로컬 소스 버전이 다르면 당시 동작 판단에는 배포 증거를 사용합니다. 로그와 재현 자료에서 자격 증명과 민감한 식별자를 가립니다.
