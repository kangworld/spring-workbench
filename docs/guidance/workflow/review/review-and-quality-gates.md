# 리뷰 및 품질 게이트 기준

본 문서는 Review Agent, Test Agent, 전역 작업 흐름이 공통으로 사용하는 품질 게이트 언어와 판정 기준을 정의합니다.
리뷰 결과, 테스트 차단 여부, 최종 배포 가능 판단은 본 문서의 상태값과 판정 규칙을 따릅니다.

## 1) 적용 범위
- 리뷰 결과를 `CLEARED`, `CLEARED_WITH_RISKS`, `BLOCKED`, `STALE` 중 하나로 판정할 때 사용합니다.
- 현재 변경으로 인한 테스트 실패가 전체 상태에 어떤 영향을 주는지 판단할 때 사용합니다.
- 리뷰 결과를 승인 가능 상태인지, 차단 상태인지, 재리뷰가 필요한 상태인지 해석할 때 사용합니다.

## 2) 상태값 정의
- `CLEARED`: 현재 작업에 필요한 입력과 검증 결과가 확인되고, 차단 이슈가 없으며, 리뷰 기준 커밋이 최신 상태인 경우
- `CLEARED_WITH_RISKS`: 차단 이슈는 없지만 낮은 심각도의 이슈, 미검증 지점, 사용자가 인지해야 할 잔여 리스크가 남아 있는 경우
- `BLOCKED`: `High` 또는 `Medium` 이슈가 남아 있거나, 현재 변경으로 인한 테스트 실패가 남아 있거나, 작업 완료에 필요한 입력 또는 검증 결과가 누락된 경우
- `STALE`: 리뷰 기준 커밋 이후 추가 커밋이 발생해 기존 리뷰 결과를 그대로 신뢰하기 어려운 경우

## 3) 판정 순서
1. 현재 작업에 필요한 입력과 검증 결과의 존재 여부를 확인합니다.
2. 현재 변경으로 인한 테스트 실패와 아직 해결되지 않은 `High` / `Medium` 이슈를 확인합니다.
3. 리뷰 기준 커밋과 현재 커밋이 같은지 비교합니다.
4. 차단 이슈는 없지만 남아 있는 낮은 심각도의 이슈, 미검증 지점, 문서 최신성 우려를 잔여 리스크로 집계합니다.
5. 상태값을 확정합니다.

## 4) `STALE` 판정 규칙
- 리뷰 이후 새 커밋이 추가되면 기존 결과는 `STALE`로 봅니다.
- `STALE`은 "예전 리뷰가 틀렸다"는 뜻이 아니라 "현재 HEAD에 대한 판정으로 재사용할 수 없다"는 뜻입니다.
- `STALE` 상태에서는 과거 리뷰 항목 자체를 참고할 수는 있지만, 최종 승인/차단 판단은 재리뷰 기준으로 다시 내려야 합니다.

## 5) 잔여 리스크 집계
- 잔여 리스크에는 차단하지는 않지만 사용자가 알아야 하는 항목만 포함합니다.
- 예:
  - 낮은 심각도의 이슈
  - 문서 최신성 우려
  - 테스트 미커버리지
  - 운영 영향은 있으나 아직 실환경에서 검증되지 않은 변경
- 이미 `BLOCKED`를 만든 `High` / `Medium` 이슈는 잔여 리스크 수에 포함하지 않습니다.

## 6) 근거 수준 원칙
- 모든 리뷰 판단은 코드, 테스트 결과, 로그, 요구사항 문구, 재현 절차처럼 확인 가능한 근거를 바탕으로 해야 합니다.
- 근거가 충분한 이슈와, 추가 확인이 필요한 의심 지점은 구분해서 다룹니다.
- 확신도가 낮은 내용은 차단 이슈로 단정하지 말고, 검토 필요 항목 또는 후속 확인 대상으로 남깁니다.

## 7) 승인 해석
- 승인 가능: `CLEARED`, `CLEARED_WITH_RISKS`
- 차단: `BLOCKED`, `STALE`
